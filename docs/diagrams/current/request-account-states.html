Reglas verificadas

Una solicitud solo se resuelve mientras está PENDING; no hay reapertura. Aprobar crea un usuario INACTIVE. La activación por token consume el token y establece la contraseña; la activación administrativa exige que la contraseña ya exista. Desactivar al último administrador activo está prohibido mediante una transacción serializable.

Fuentes: schema.prisma, user-requests.service.ts, account-activation.service.ts, users.service.ts, sus pruebas unitarias y prisma/seed.ts.

Limitaciones actuales

  • No existe operación que escriba BLOCKED.
  • No existe operación que escriba o limpie lockedAt.
  • activate() y deactivate() aceptan salir desde BLOCKED.
  • El seed y el default de Prisma inicializan usuarios directamente en ACTIVE.
