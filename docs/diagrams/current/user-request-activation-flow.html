Solicitud y activación de usuario

Responsabilidades, decisiones y brecha de entrega del token al 13 de agosto de 2026.

Reglas verificadas

La solicitud empieza en PENDING. Solo un administrador puede aprobarla o rechazarla. Aprobar reclama la solicitud, crea un usuario INACTIVE y persiste el hash del token dentro de una transacción. Activar exige contraseñas coincidentes, token existente, no usado y vigente, y usuario todavía inactivo; luego consume el token y cambia el usuario a ACTIVE transaccionalmente.

Fuentes: user-requests.service.ts, account-activation.service.ts, sus pruebas unitarias y activation-token-delivery.service.ts.

Brecha actual

  • deliver() es un stub sin proveedor.
  • La aprobación no devuelve el token.
  • El endpoint de activación funciona solo si el cliente obtiene un token por otro medio.
